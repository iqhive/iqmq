# Contributing

Contributions to this project are welcome.

## Before you start

Please first check existing issues, discussions, and pull requests to avoid
duplicating work. If you plan to work on an existing issue, leave a comment
describing your approach.

For a substantial change, please open an issue or start a discussion using the
project's collaboration tools before starting work. We ask you describe the
problem, your proposed approach, and any compatibility implications so
maintainers can discuss the scope with you.

The purpose of this is to ensure that the change is made in a way that is
consistent with the project's goals and architecture, so it can be maintained
long-term.

Please consult the README and development documentation for setup, build, and
test instructions. Please follow the existing code style, and include tests and
documentation updates.

## Reporting bugs and requesting features

Use the project's issue tracker and issue templates where available. If the
issue tracker is not available, please follow the contact instructions in
the repository's README.

For bug reports, include:

- A clear description of the problem.
- Steps to reproduce it, preferably with unit tests or a minimal example.
- The expected and actual behaviour.
- Relevant project versions, environment details, and sanitized logs.

For feature requests, explain the use case, the problem the feature would solve,
and any alternatives you have considered.

Do not disclose suspected security vulnerabilities in public issues,
discussions, or pull requests. Instead, submit these as a security
vulnerability report. If this is unavailable, email security@iqhive.com
privately.

## Submitting a pull request

1. Fork the repository (unless you have permission to create a branch
   directly) and create a branch for your change.
2. Make a focused change. Keep unrelated fixes or refactoring in separate
   pull requests.
3. Add or update tests and documentation to ensure the overall code
   coverage does not decrease as a result of your change.
4. Run the relevant build, test, formatting, and lint checks documented by
   the project.
5. Open a pull request against the main branch.
6. Complete the pull request template. Explain:
   - What changed and why.
   - Any related issues, with links or issue references.
   - Which checks you ran and their results.
   - Any breaking changes, compatibility considerations, or migration steps.
7. Respond to review feedback and update your branch as needed.

Clearly mark the pull request as a work in progress if it is not ready for
review. Identify unfinished work, checks you could not run, and any known
limitations.

Maintainers may request changes or decline a contribution based on the
project's scope, compatibility requirements, or maintenance needs.

## Information you must not submit

Do not include secrets, credentials, personal or confidential information,
or material that you do not have permission to contribute. Check code,
tests, examples, logs, screenshots, and commit history before publishing.
